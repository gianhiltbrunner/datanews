# dbt Labs unveils dbt v2 at its annual summit, and a Rust rewrite starts breaking things

dbt Labs used its annual summit to showcase dbt v2, and a practitioner migration write-up is already documenting what changes when dbt Core moves to a Rust-based engine. Beyond that, the strongest pieces were opinion and analysis: a case for dbt over raw warehouse SQL, an essay on the gap between a "correct" table and one people actually use, and a substack piece on why decision support — not data systems — is what businesses actually care about. Cube shipped a release patching open security advisories; most other releases in the window were routine bug-fix patches.

## Top stories
- **[dbt Core v2.0 Just Rewrote Itself in Rust — Here's What Actually Breaks When You Migrate](https://medium.com/tech-with-abhishek/dbt-core-v2-0-just-rewrote-itself-in-rust-heres-what-actually-breaks-when-you-migrate-fbd16c84b666)** — Tech with Abhishek (Medium). Written alongside dbt Labs' annual summit unveiling of dbt v2, this migration write-up walks through what broke moving to the new Rust-based core, referencing a Fivetran tie-in and a string of GitHub issues surfaced during early upgrades. *Why it matters:* a core-engine rewrite this size means analytics engineers should expect migration friction before adopting v2.
- **[The Table Was Correct but Nobody Used It](https://blog.dataengineerthings.org/the-table-was-correct-but-nobody-used-it-9c621e34f06a?source=rss------analytics_engineering-5)** — Data Engineer Things (Medium). Examines the distance between a clear business question and the data people actually rely on to answer it, arguing correctness alone doesn't guarantee adoption. *Why it matters:* it's a reminder that modeling for correctness and modeling for usage are different jobs.
- **[Why dbt When We Already Have Snowflake?](https://medium.com/@nazeer.td/why-dbt-when-we-already-have-snowflake-0247acc4dc88?source=rss------dbt-5)** — Medium. Responds directly to the objection that Snowflake's MERGE, tasks and stored procedures already cover what dbt does. *Why it matters:* it's a useful counter-argument for teams currently debating whether they need a transformation layer at all.
- **[Building Intelligent Decision Support Systems](https://sqlpatterns.com/p/building-intelligent-decision-support)** — Data Patterns (Ergest Xheblati). Argues that businesses don't care about data systems themselves, only the decisions they enable, and that BI's "actionable insights" promise has rarely been delivered on. *Why it matters:* it reframes analytics engineering priorities around decisions rather than pipelines and models.
