# Polars previews its 2.0 breaking changes as the rest of the feed goes quiet

Data engineering feeds were almost entirely SEO-driven Medium and DEV posts, wire stories about unrelated "data engineering" keyword matches, and no publishing from the usual substack or engineering-blog regulars. The one concrete release was a Polars 2.0 release candidate spelling out its breaking changes, alongside a reflective piece on the volatility of deploying LLM serving on Databricks and a small open-source project wiring an MCP server to multiple Iceberg catalogs.

## Top stories
- **[Python Polars 2.0.0-rc.2](https://github.com/pola-rs/polars/releases/tag/py-2.0.0-rc.2)** — Polars releases. The first release candidate for Polars 2.0 reads Parquet ENUM columns as `pl.String`, deprecates `cut`/`qcut`, removes the legacy `POLARS_STREAMING_CHUNK_SIZE` env var, and introduces a new `Map` dtype, alongside parquet-predicate and float-literal performance work. *Why it matters:* this is the clearest signal yet of what breaks when Polars users move to 2.0.
- **[Databricks LLM (APIs)/Modeling Serving. Thoughts from the Frontline.](https://dataengineeringcentral.substack.com/p/databricks-llm-apismodeling-serving)** — Data Engineering Central. A practitioner reflects on how fast the AI model landscape moves, arguing that teams deploying production LLM serving on Databricks rarely get to feel settled before the next "improved" model or API shifts underneath them. *Why it matters:* it's a candid counterpoint to vendor messaging about production-readiness in AI data serving.
- **[One Iceberg MCP Server, Seven Catalogs: What It Takes to Reach Each One](https://dev.to/aws-builders/one-iceberg-mcp-server-seven-catalogs-what-it-takes-to-reach-each-one-jp5)** — DEV. A single MCP server exposes four read-only tools — list tables, describe table, and two more — against seven different Iceberg REST catalog implementations, switching catalogs via one environment variable. *Why it matters:* it's a concrete example of wiring coding agents directly into lakehouse metadata.
