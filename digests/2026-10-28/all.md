# Oracle's cloud-partnership push and dbt 2.0's licensing split headline the day

The day's biggest news is Oracle expanding its OCI partnerships with both Snowflake and Google Cloud at Oracle AI World, while analytics engineers are still working through what dbt 2.0's split into a proprietary Fusion build and an Apache-2.0 `dbt-oss` distribution means for their upgrade path. Elsewhere, DuckDB's blog highlighted the sleeper features in this week's 2.0 LTS release, and Uber and ClickHouse each published notable engineering results.

## Top 5 across domains
- **[Data Platform Engineering]** **[Snowflake and Oracle: Bringing the AI Data Cloud to OCI](https://www.snowflake.com/content/snowflake-site/global/en/blog/snowflake-oracle-partnership-ai-data-cloud-oci)** — Oracle deepened ties with both Snowflake (AI Data Cloud now native on OCI) and Google Cloud (TPU access, tighter Gemini Enterprise integration) at Oracle AI World.
- **[Data Engineering]** **[Gems of DuckDB 2.0.0](https://duckdb.org/2026/10/26/gems-of-duckdb-200)** — a follow-up to this week's LTS release detailing practical additions like a Python appender, partitioned `COPY` output and `SECURE VIEW`.
- **[Analytics Engineering]** **[UPDATE dbt 2.0: what changes when you upgrade, and the dbt vs dbt-oss split](https://www.reddit.com/r/DataBuildTool/comments/1xhis84/update_dbt_20_what_changes_when_you_upgrade_and/)** — `pip install dbt` now installs the proprietary Fusion build, with the open-source engine moved to `dbt-oss`, and upgrading requires clearing every deprecation warning first.
