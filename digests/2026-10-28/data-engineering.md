# DuckDB 2.0's best features and Uber's compute-scheduling rework lead the day

A quiet day for breaking news, but strong follow-up content: DuckDB's blog dug into the standout features of this week's 2.0 LTS release, Uber detailed a rework of CPU allocation for stateful workloads, and a Data Engineering Weekly opinion piece asked whether data models still matter once agents are building the pipelines. Two practitioner write-ups covered silent failure modes in Kafka-based CDC and retention.

## Top stories
- **[Gems of DuckDB 2.0.0](https://duckdb.org/2026/10/26/gems-of-duckdb-200)** — Hacker News / duckdb.org. A follow-up to this week's 2.0 LTS release highlighting practical additions: a Python client appender for batched row writes, `COPY` support for custom partition directory paths and per-partition sorting, `SECURE VIEW` to hide underlying data from `stats()` and query plans, and `setval` for resetting sequences after bulk loads. *Why it matters:* these are the kind of pipeline-facing details that don't make a release announcement but change how teams actually use DuckDB in production.
- **[Uber Moves beyond CPU Cores with Performance-Aware Scheduling for Stateful Workloads](https://www.infoq.com/news/2026/10/uber-cpu-stateful-workloads/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering)** — InfoQ. Uber introduced Normalized Compute Units (NCUs) to make CPU allocation more consistent across its highly heterogeneous server fleet. *Why it matters:* a concrete pattern for teams running stateful workloads on mixed hardware who are tired of CPU-core allocation being an unreliable proxy for actual performance.
- **[Do We Still Need Data Models?](https://www.dataengineeringweekly.com/p/do-we-still-need-data-models)** — Data Engineering Weekly. Argues that as agents increasingly build data systems themselves, data models become more important, not less, because they're how humans understand the decisions behind agent-built pipelines. *Why it matters:* a pushback on the idea that AI agents make traditional data modelling discipline obsolete.
- **[The Silent CDC Bug: Data Loss With No Errors](https://dev.to/pipelinewhiteboard/the-silent-cdc-bug-data-loss-with-no-errors-5ahh)** (part of a series that also covers [Debezium Postgres to Kafka: Every Setting Explained](https://dev.to/pipelinewhiteboard/debezium-postgres-to-kafka-every-setting-explained-1fen)) — DEV. Walks through four ways a healthy-looking Debezium-to-Kafka CDC pipeline can silently lose rows, plus the reconciliation check that catches all of them, and separately details which Debezium defaults cause production trouble. *Why it matters:* "everything's green but rows are missing" is one of the hardest CDC failure modes to catch, and this gives a concrete detection method.
- **[Kafka Retention Does Not Start When Your Consumer Fails](https://medium.com/@kirill.fedorov2112/kafka-retention-does-not-start-when-your-consumer-fails-202e2b019363?source=rss------data_engineering-5)** — Medium. Explains how byte limits, partition skew, compaction and reset policies interact to change a pipeline's actual recovery window after a consumer outage. *Why it matters:* a common source of surprise outages when teams assume retention time alone determines how much buffer they have.
