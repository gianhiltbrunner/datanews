# A ClickHouse team traces 32 ms of tail latency to a reset TCP congestion window

A strong day for platform engineering, led by a detailed ClickHouse latency investigation and several notable GA launches: native data-quality checks on Amazon EMR, Snowflake's Semantic Studio, and new SQL pool isolation in Microsoft Fabric. Databricks also shared how Flo Health built safety controls around open models serving 81 million users.

## Top stories
- **[Chasing that 32 ms tail latency in ClickHouse](https://clickhouse.com/blog/chasing-32ms-tail-latency-clickhouse)** — ClickHouse Blog. A customer saw an extra ~32 ms on simple SELECT queries after idle periods; the team traced it to unbatched Native protocol metadata packets overflowing a reset TCP congestion window, reproduced it with network namespaces, and fixed it by batching the packets. *Why it matters:* a rigorous, reproducible root-cause story for a class of latency bug that's easy to misattribute to the query engine itself.
- **[Bring data quality to your Amazon EMR workloads with Amazon EMR Data Quality built on AWS Glue Data Quality](https://aws.amazon.com/blogs/big-data/bring-data-quality-to-your-amazon-emr-workloads-with-amazon-emr-data-quality-built-on-aws-glue-data-quality/)** — AWS Big Data Blog. AWS Glue Data Quality is now available natively in EMR's Spark runtime (emr-spark-8.1.0), letting teams reuse the same DQDL rulesets for lightweight inline validation or an Iceberg Write-Audit-Publish workflow. *Why it matters:* removes the need to bolt Glue Data Quality onto EMR jobs as a separate integration.
- **[Introducing Semantic Studio: The Semantic View IDE](https://www.snowflake.com/content/snowflake-site/global/en/blog/semantic-studio-ga)** — Snowflake Blog. Semantic Studio is now generally available for authoring, debugging and deploying Snowflake semantic views, with git versioning and CI/CD built into Snowflake Workspaces. *Why it matters:* brings standard software-engineering workflow to semantic layer development inside the warehouse.
- **[How Flo Health built safer, more useful open models with Databricks AI Runtime](https://www.databricks.com/blog/how-flo-health-built-safer-more-useful-open-models-databricks-ai-runtime)** — Databricks Blog. Serving 81 million monthly users, Flo Health describes the safety and reliability bar it holds generative AI features to, and how it used Databricks AI Runtime to meet it. *Why it matters:* a real-team account of operating open models at a scale where failures are consequential.
