# Databricks shares lessons from running 100 PR-scale Postgres branches

Today's strongest item is engineering, not announcements: Databricks detailed how Lakebase branching gave Snorkel AI disposable, production-like Postgres copies for CI. On the vendor side, Snowflake disclosed a large Saudi Arabia investment and a Python/multi-cloud push, and reverse-ETL vendor Hightouch raised new funding.

## Top stories
- **[Lakebase branching for CI/CD: lessons from 100 PR databases](https://www.databricks.com/blog/lakebase-branching-cicd-lessons-100-pr-databases)** — Databricks Blog. Snorkel AI needed a fresh copy of its roughly 2.5 TB production database for every pull request, but restores took about 20 minutes, so teams fell back on shared staging data or synthetic data that missed real edge cases; using Lakebase's copy-on-write branching, with a main branch synced from production via AWS DMS and a branch per PR created through an API, databases became ready in under a minute, with TTLs removing them automatically. *Why it matters:* a concrete pattern — TTLs, scale-to-zero compute, short-lived OAuth tokens instead of passwords — for giving CI pipelines and AI agents disposable, production-like data without ballooning storage costs.
