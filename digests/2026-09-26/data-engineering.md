# Perplexity replaces DynamoDB with homegrown CobbleDB to cut query latency 5x

Real architecture writing carried the day against a wall of Medium/DEV SEO filler and Google News job postings: Perplexity's key-value store migration, a Netflix identity deep-dive for Spark on managed compute, and a practitioner's case against blanket real-time requirements. No releases landed in today's window.

## Top stories
- **[Home Made CobbleDB Replaces DynamoDB at Perplexity to Cut Query Latency 5x and Reduce Cloud Storage](https://www.infoq.com/news/2026/09/cobbledb-perplexity/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering)** — InfoQ. Perplexity migrated its search infrastructure from Amazon DynamoDB to CobbleDB, an internally built Rust key-value store, cutting latency and storage costs while handling large document batches at high query volumes. *Why it matters:* a concrete data point on when a managed store stops being the right fit and a custom engine pays off.
- **[Trading a Cloud Identity for Your Own: Workload Attestation on Managed Compute](https://netflixtechblog.com/trading-a-cloud-identity-for-your-own-workload-attestation-on-managed-compute-516d5a29b252?source=rss----2615bd06b42e---4)** — Netflix Tech Blog. Netflix describes how it closes the gap between a cloud provider's IAM identity and its own internal identity system for Apache Spark workloads running on managed compute, where you can't bootstrap identity the way you would on infrastructure you control. *Why it matters:* a reusable pattern for teams running Spark on managed platforms who need their own trust model, not just the provider's.
- **[Do You Actually Need Real-Time Data?](https://seattledataguy.substack.com/p/do-you-actually-need-real-time-data)** — Seattle Data Guy. Argues that "real-time" requests from stakeholders often mean something far looser than sub-second freshness once you dig into what they actually need. *Why it matters:* a useful pushback for engineers who get real-time requirements handed down without a freshness SLA attached.
- **[Stateless MCP Removes Session Affinity Requirements for AWS Server Deployments](https://www.infoq.com/news/2026/09/aws-stateless-mcp/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering)** — InfoQ. AWS details how the latest Model Context Protocol spec drops protocol-level sessions and sticky-session requirements for remote MCP servers, pushing state, retries and idempotency to other layers. *Why it matters:* simplifies horizontal scaling for teams standing up MCP servers over their data infrastructure.
