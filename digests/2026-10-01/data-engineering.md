# DuckDB v2.0 Nears Release as LinkedIn and Atlassian Drop JSON for Binary

DuckDB confirmed a v2.0.0 preview is available ahead of a release in the coming weeks, while a wire report detailed how LinkedIn and Atlassian cut pipeline latency and cost by replacing JSON with binary formats. Elsewhere, DEV contributors published detailed, scar-tissue write-ups on PySpark production failure modes, entity-resolution blocking logic, and catching bad data at the pull request.

## Top stories
- **[🦆 DuckDB v2.0.0 ships in a few weeks...](https://bsky.app/profile/duckdb.org/post/3mws7kon4oc2p)** — DuckDB (Bluesky). DuckDB announced v2.0.0 will ship in the coming weeks and published a preview release of the v2.0.0-dev clients for testing. *Why it matters:* a major version bump for a tool central to this domain's focus, worth testing before the cutover.
- **[LinkedIn and Atlassian Cut Latency and Costs by Ditching JSON for Binary Formats](https://news.google.com/rss/articles/CBMirgFBVV95cUxNVnVGNzg1NWF0YmtSMkNUYTF6aHFwdlVxMEtLUlp1RWgtbUFOREVtZlBpNEs0VXNHZWRkaVVlckJoWlRuTlI5Y3FubE5rbElrQjQ4UzZzZDRkM1ZwazVoWEFJQXRYRTVNVE1MWUxJWUdnVW9XaHNCNzlMT01kU0ktUWI4MXBQTFVpLVpZUWpIZlV0VzdnWTJ1V2gtMHI3ZFZIcl91STBBMTlyRnVraXc?oc=5)** — news.lavx.hu via Google News. Reports that LinkedIn and Atlassian reduced latency and infrastructure costs by replacing JSON with binary serialization formats in their data pipelines. *Why it matters:* a concrete data point for teams weighing the cost of text-based wire formats at scale.
- **[Two PySpark contracts Staff DEs learn on a bad Tuesday: foreachBatch restarts and applyInPandas skew](https://dev.to/firfircelik/two-pyspark-contracts-staff-des-learn-on-a-bad-tuesday-foreachbatch-restarts-and-applyinpandas-skew-39pa)** — DEV. Walks through two production failure modes on Databricks/PySpark: foreachBatch restarts breaking at-least-once writes and watermark-dedupe state, and applyInPandas skew OOMing a single worker while the rest of the cluster idles. *Why it matters:* documents failure contracts that happy-path tutorials skip entirely.
- **[The decisions in my entity resolution pipeline that I still make myself](https://dev.to/hannune/the-decisions-in-my-entity-resolution-pipeline-that-i-still-make-myself-2cl3)** — DEV. Traces a multi-day blocking-key debugging session back to Japanese 合同会社 (godo kaisha) entity names not matching their Korean counterparts, and reflects on which entity-resolution decisions still need a human rather than an LLM. *Why it matters:* a specific, reproducible example of where automated matching logic quietly fails.
- **[Stop bad data at the pull request with Great Expectations and GitHub Actions](https://dev.to/laura_cristinachicovisd/stop-bad-data-at-the-pull-request-with-great-expectations-and-github-actions-5dh)** — DEV. Shows how to fail a pull request before merge by compiling a YAML data contract into Great Expectations checks and running them in GitHub Actions. *Why it matters:* catches data quality regressions at code review instead of after data lands.
