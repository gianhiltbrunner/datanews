# A lakehouse layout benchmark finds two undocumented failure modes in Delta Lake clustering

A quiet day dominated by low-signal wire noise and beginner tutorials, but a few solid practitioner write-ups stood out: a rigorous benchmark of Delta Lake layout strategies, a real-world AWS Glue networking gotcha, and a maintainer's bug-hunting log while adding Iceberg support to Apache Hop. No tracked project shipped a notable release in this window.

## Top stories
- **[When Should You Use Liquid Clustering? Benchmarking Lakehouse Layout Strategies](https://www.infoq.com/articles/liquid-clustering-lakehouse-layout/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering)** — InfoQ. The author compares Liquid Clustering, ZOrdering and partitioning across four workload types on Delta Lake, surfacing two undocumented failure modes and a decision framework for picking a layout strategy. *Why it matters:* physical layout choices are consequential and usually made on vendor marketing rather than evidence like this.
- **[AWS Glue Concurrency Is Capped by One Subnet, Not Your Whole VPC](https://dev.to/kiran_gunturu_022085015ec/aws-glue-concurrency-is-capped-by-one-subnet-not-your-whole-vpc-1220)** — DEV. Testing on a regulated data platform showed that Glue's concurrency ceiling is the free IPs in a single subnet, not the sum across the VPC, since attaching multiple connections only adds failover, not pooling. *Why it matters:* a concrete, provable fix (size a dedicated subnet per workload) for failures that are easy to misdiagnose as a job-level problem.
- **[The Iceberg Table That Was Never Where We Wrote It](https://dev.to/kotwal-itpro/the-iceberg-table-that-was-never-where-we-wrote-it-3c0b)** — DEV. While adding native Apache Iceberg read/write support to Apache Hop (now merged to main, without needing a Spark cluster), the author hit several bugs that let every test pass while still being wrong. *Why it matters:* a candid account of the gap between "tests pass" and "the table is actually where you think it is."
- **[UTC is not a data contract. Period.](https://dev.to/sudeephazra/utc-is-not-a-data-contract-period-51dj)** — DEV. Prompted by a r/dataengineering thread about a timestamp bug that cost three days, the author argues storing instants in UTC isn't enough on its own to define a complete timestamp contract. *Why it matters:* a common, quietly expensive class of bug that "store everything in UTC" advice doesn't actually prevent.
