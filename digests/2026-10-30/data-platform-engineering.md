# ClickHouse's AI contributor and Oracle-Snowflake's deepening OCI tie-up lead a dense platform day

ClickHouse disclosed that an autonomous engineering agent has merged over 3,000 pull requests into the project in under seven months, while Oracle and Snowflake extended their OCI partnership and Google Cloud let BigQuery query Databricks-managed Iceberg tables without copying data. Snowflake also published two more posts in its "Running Snowflake in the Agent Era" series, this time on cost controls and treating scheduled agents as pipeline steps that need review gates.

## Top stories
- **[Meet GroeneAI: our autonomous contributor to ClickHouse](https://clickhouse.com/blog/meet-groeneai-our-autonomous-contributor-to-clickhouse)** — ClickHouse Blog. ClickHouse introduces GroeneAI, an autonomous engineering agent that has contributed more than 3,000 merged pull requests to the project in under seven months. *Why it matters:* A concrete, quantified data point on how far AI agents have moved into maintaining production open-source infrastructure.
- **[Oracle Expands Native AI and Data Services on OCI with Snowflake](https://news.google.com/rss/articles/CBMiqgFBVV95cUxQM0pLN05oRjZtM1RsRUR4Z3k0bGJ1bHhYTjNHNjhucWlNNFFtSlVBUEgwSXpqR1ZNVWVReFZrWC1keW1ZcnlTZW1xcmgxTFJIMjJHMTVhYUlRLTBXZXpFQV84d1RLVFlFUXZkSG5tcFlfMWpuMHZKMmtPLVFrclpXemNmdjE3d2xZbWppUlVKU3czTEVlSER5dXllUkNKX2I3MWlsVWVpOVg0Zw?oc=5)** — iTWire. Oracle deepened its OCI partnership with Snowflake, bringing Snowflake's AI Data Cloud onto Oracle Cloud Infrastructure as a first-party service. *Why it matters:* Two warehouse vendors that are usually competitors are instead standardizing on each other's infrastructure for AI workloads.
- **[Querying Databricks Apache Iceberg Tables with the borderless Lakehouse](https://cloud.google.com/blog/products/data-analytics/querying-databricks-iceberg-tables-with-google-clouds-lakehouse/)** — Google Cloud — Data Analytics. BigQuery can now query Databricks-managed Apache Iceberg tables directly, zero-copy, removing the need to build pipelines that duplicate data between the two platforms. *Why it matters:* Cuts a common source of storage cost, latency and security-control fragmentation for teams running both Databricks and BigQuery.
- **[Budgets, Quotas, and Monitors: The Cost Controls I Map Before Agents Go Wider](https://medium.com/snowflake/budgets-quotas-and-monitors-the-cost-controls-i-map-before-agents-go-wider-7554c3301c4d?source=rss----34b6daafc07---4)** — Snowflake Engineering (Medium). Part 3 of Snowflake's "Agent Era" series digs into which cost controls actually stop spend versus just report on it, building on query-tag-based credit tracking across adaptive warehouses. *Why it matters:* Practical guidance for platform teams about to let agents loose on warehouse compute.
- **[Introducing the data engineering agent for Fabric (Project Osmos)](https://community.fabric.microsoft.com/t5/Fabric-Updates-Blog/Introducing-the-data-engineering-agent-for-Fabric-Project-Osmos/ba-p/5377944)** — Microsoft Fabric Blog. Microsoft's new Fabric agent targets a specific failure mode: an AI-generated Spark job can run successfully and still silently produce wrong results on the full dataset. *Why it matters:* Addresses the trust gap in AI-written pipeline code rather than just generating more of it.
