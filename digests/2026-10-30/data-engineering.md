# Practitioner write-ups on Iceberg, CDF and window functions outshine a quiet news day

Data engineering news was mostly recruitment ads, stock chatter and AI-trends roundups, but several practitioner deep-dives stood out: field notes on running Apache Iceberg in production, a guide to Delta Lake's Change Data Feed, and a breakdown of why window functions are expensive. On the release side, Apache Kafka 4.4.0 shipped and dlt 1.32.0 landed a breaking change to how it handles naive timestamps in SCD2 columns.

## Top stories
- **[Apache Iceberg in a data lake: how it works and how to keep it fast, cheap and simple](https://dev.to/mashaa/apache-iceberg-in-a-data-lake-how-it-works-and-how-to-keep-it-fast-cheap-and-simple-509m)** — DEV. Field notes from running Iceberg tables for transaction reconciliation on S3, Glue, Spark and Athena, covering the traps hit and the settings that cut cost and improved query speed. *Why it matters:* Iceberg adoption guidance from a team that actually operates it beats another conceptual overview.
- **[Delta Lake Change Data Feed on Azure Databricks: readChangeFeed, Incremental MERGE, and the Retention Traps](https://dev.to/karanpulyala/delta-lake-change-data-feed-on-azure-databricks-readchangefeed-incremental-merge-and-the-3i8o)** — DEV. Walks through turning on Delta Lake's Change Data Feed to replace full-table Silver-to-Gold rewrites with incremental MERGE, plus the retention and schema traps that break it. *Why it matters:* A concrete fix for a pattern — full rewrites on every run — that quietly becomes unaffordable as tables grow.
- **[How Window Functions Actually Scale (or Don't)](https://dev.to/aniketsoni/how-window-functions-actually-scale-or-dont-25i)** — DEV. Argues that `OVER(PARTITION BY ... ORDER BY ...)` isn't free SQL sugar but a physical execution plan that forces a cluster-wide shuffle, and explains how that shuffle cost compounds. *Why it matters:* A reminder that query syntax choices have direct, often underestimated compute-budget consequences.
- **[A vendor bar for a day nothing traded - why our completeness check was 97% wrong](https://dev.to/alexbsolodev/a-vendor-bar-for-a-day-nothing-traded-why-our-completeness-check-was-97-wrong-a1a)** — DEV. A team's first data-completeness check against an exchange calendar found 30,581 missing stock-days across 738 instruments — and then turned out to be 97% wrong itself, with nothing in the data flagging it. *Why it matters:* A concrete example of how a plausible-looking data-quality check can itself be the bug.
- **[Stop Tuning Parquet by File Size Alone](https://medium.com/@kirill.fedorov2112/stop-tuning-parquet-by-file-size-alone-70165dd8edb6?source=rss------data_engineering-5)** — Medium. A DuckDB-first checklist for Parquet row groups, pruning and safe layout changes, arguing file size alone is the wrong tuning lever. *Why it matters:* Parquet layout mistakes are easy to make and expensive to unwind once a lakehouse is in production.

## Releases & tools
- **[Introducing Apache Kafka 4.4.0](https://www.confluent.io/blog/introducing-apache-kafka-4-4-0/)** — The Apache Software Foundation's latest Kafka release, described as carrying "many new features and improvements."
