# A 250-line DuckDB+Make tool rivals dbt, and GKE ships faster model cold starts

Today's window was dominated by SEO-farm Medium/DEV posts and Google News hits pulled in by broad keyword matches (recruitment ads, unrelated stories), leaving a thin field of real content: a minimalist dbt alternative built on DuckDB's own SQL parser, benchmarks for GKE's new pod-snapshot feature, and a Reddit debate over how data engineers actually feel about dbt.

## Top stories
- **[Show HN: Minimal dbt-style SQL builds with DuckDB and Make](https://github.com/ltrgoddard/duckdb.mk)** — Hacker News (DuckDB). Built on DuckDB's own `json_serialize_sql` function to parse SQL into an AST, this ~250-line tool gives dbt-style dependency resolution between named `SELECT` queries using just DuckDB and Make, skipping dbt's configuration and boilerplate. *Why it matters:* shows how much of dbt's core value — reproducible, referenceable SQL builds — can be replicated with far less tooling for smaller projects.
- **[GKE Pod Snapshots Cut Model Load Times, and Move the Work to Snapshot Lifecycle Management](https://www.infoq.com/news/2026/09/gke-pod-snapshots-benchmarks/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering)** — InfoQ. Google's benchmarks show GKE Pod snapshots — which checkpoint CPU and GPU memory through gVisor into Cloud Storage — cutting startup latency by up to 89% and loading a 70B-parameter model in 37 seconds; practitioners note that snapshot invalidation, keyed to a spec hash plus machine, kernel and driver versions, may be the harder problem in practice. *Why it matters:* faster, more predictable cold starts for teams serving large models or bursty compute on GKE.
