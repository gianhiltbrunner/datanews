# Databricks buys spreadsheet startup Row Zero to give Genie governed spreadsheets

Nearly twenty Google News outlets covered the same Databricks–Row Zero acquisition, but the real platform news was Google Cloud's new agentic database architecture for AlloyDB, a Delivery Hero case study on moving from batch to streaming, and a wave of routine AWS feature announcements.

## Top stories
- **[Databricks Acquires Microsoft Excel Competitor Row Zero](https://news.google.com/rss/articles/CBMinAFBVV95cUxQU3gtTnRKU1FLTFg2UnhBYW5YR1RZb0hoN0NxOHZDU195TkJ3OEtLbk5WblBaVXJGeE9nUFdQYzcwUFJwWEN0cjVBUVQ0aFVOY3ZBLXJlUWZ4anlQTVBxMW1BNnNjUnhlRl9McnNPVTFYTXR4Ylk5OFowRmFnSmdXRmZyeXNzOFRIYkRTeElpVlY4QUVpcXdkVjNSclY?oc=5)** — The Information (via Google News). Databricks is acquiring spreadsheet startup Row Zero to bring live, governed spreadsheets into Genie, its AI "coworker" product. *Why it matters:* pushes Databricks' AI agent layer toward a familiar, governed end-user surface — spreadsheets — rather than just dashboards or chat.
- **[AlloyDB delivers PostgreSQL for agents: Real-time data at agent scale, with full workload isolation](https://cloud.google.com/blog/products/databases/announcing-postgresql-for-agents-in-alloydb/)** — Google Cloud. AlloyDB can now provision sandboxed, fully isolated database instances in seconds (in preview) so bursts of concurrent AI agents running dense reasoning loops don't overwhelm a mission-critical operational database. *Why it matters:* a concrete answer to a problem platform teams are only starting to hit — agents as an unpredictable new class of OLTP load.
- **[How Delivery Hero rebuilt real-time ad measurement with Apache Flink](https://aws.amazon.com/blogs/big-data/how-delivery-hero-rebuilt-real-time-ad-measurement-with-apache-flink/)** — AWS Big Data Blog. Delivery Hero moved its ad-measurement pipeline from hourly batch processing to Amazon Managed Service for Apache Flink, cutting the event-to-record gap from 61 minutes to 1.2 seconds and cutting monthly operating cost by about 57%. *Why it matters:* a rare case study with hard before/after numbers for a batch-to-streaming migration.
- **[Running open-Jev in SQL on Databricks](https://www.databricks.com/blog/running-open-jev-sql-databricks)** — Databricks Blog. Covers running Jev, a newly launched "System One" decision model that answers typed yes/no or multiple-choice questions instead of generating text, directly from SQL. *Why it matters:* an early, concrete instance of a fast decision model wired into the query layer itself rather than run through a full LLM call.
