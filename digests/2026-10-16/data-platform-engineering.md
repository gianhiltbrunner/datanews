# Atlassian details the security lakehouse it built on Databricks to cut alert noise

Vendor blogs carried the day's strongest engineering content: Atlassian walked through the OCSF-based security lakehouse it built on Databricks, Snowflake made Postgres-to-Snowflake data mirroring generally available, and a Snowflake engineer wrote candidly about what agents are doing to data governance. ClickHouse made the case for offloading settled OLTP data instead of scaling Postgres further. Beyond that, the feed was mostly Snowflake stock-ticker wires and routine AWS regional expansions.

## Top stories
- **[Reducing the noise: How Atlassian built an OCSF security lakehouse on Databricks](https://www.databricks.com/blog/reducing-noise-how-atlassian-built-ocsf-security-lakehouse-databricks)** — Databricks Blog. Atlassian consolidated two decades of security logging at global scale into an OCSF-standardized lakehouse on Databricks. *Why it matters:* a real team's architecture for taming security log volume, a problem any platform team running multi-year logging eventually hits.
- **[Data Mirroring Is GA: Replicate Postgres Data to Snowflake in Seconds](https://www.snowflake.com/content/snowflake-site/global/en/blog/data-mirroring-ga-snowflake-postgres)** — Snowflake Blog. Inserts, updates, deletes and schema changes now replicate automatically from Snowflake Postgres to Snowflake analytics with no pipeline or extra infrastructure to manage. *Why it matters:* removes a whole category of CDC pipeline work for teams running Postgres and Snowflake side by side.
- **[Governing Data and AI Agents in Snowflake: A Data Engineer's Field Notes](https://medium.com/snowflake/governing-data-and-ai-agents-in-snowflake-a-data-engineers-field-notes-0662c602b404?source=rss----34b6daafc07---4)** — Snowflake Engineering (Medium). A practitioner's field guide to governance once an LLM can run SQL on your behalf, arguing agents expose every gap in masking policies and untracked tables. *Why it matters:* a concrete warning that governance debt becomes an active security risk the moment agents start querying the warehouse.
- **[OLTP is expensive, you can ClickHouse it.](https://clickhouse.com/blog/oltp-is-expensive-you-can-clickhouse-it)** — ClickHouse Blog. Makes the case for offloading settled Postgres data to ClickHouse to cut storage and query costs while keeping active transactions in Postgres. *Why it matters:* a concrete pattern for teams facing rising OLTP storage bills without a full migration off Postgres.
