# Google's Data Agent Kit reaches GA, splitting agent guardrails between skills and IAM

Google's Data Agent Kit reached general availability, giving coding agents guardrails across skills and IAM, while Netflix published a tool for measuring the blast radius of shared-library changes. Beyond those two, the day was thin on substance: Reddit threads on work shifting from pipelines to semantic layers, and the ecosystem kept digesting DuckDB 2.0's rollout.

## Top stories
- **[Google's Data Agent Kit Hits GA, Splitting Agent Guardrails Between Skills and IAM](https://www.infoq.com/news/2026/10/data-agent-kit-ga/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering)** — InfoQ. Google's Data Agent Kit is now generally available: a free set of MCP tools and 37 open-source skills connecting coding agents to more than fifteen Google Data Cloud services, with two separate guardrail layers — a skill that asks the agent to stop, and an IAM policy that refuses the call outright. *Why it matters:* as agents write more pipeline code, teams need to know which guardrail is advisory and which is actually enforced.
- **[Beyond API Compatibility: Building a Tool to Measure the Blast Radius of Library Changes](https://netflixtechblog.com/beyond-api-compatibility-building-a-tool-to-measure-the-blast-radius-of-library-changes-9474f2fd4f90?source=rss----2615bd06b42e---4)** — Netflix Tech Blog. Netflix's Java Platform team built Quasar, which connects a proposed shared-library API change to the consumer repositories that actually reference the changed symbols, giving producers evidence before they release. *Why it matters:* the same blind spot — shipping a change without knowing who downstream depends on it — applies to shared pipeline libraries and internal SDKs everywhere.
