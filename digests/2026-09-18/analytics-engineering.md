# dbt v2.0 reaches general availability, rewritten in Rust

dbt Labs' Fusion engine graduated from beta to GA under a new name — plain "dbt" — with a from-scratch Rust rewrite, local SQL comprehension, and a 10x-smaller Parquet-based metadata format, alongside new Fivetran integration announcements at dbt Summit. Elsewhere, two engineering teams wrote up hard-won lessons on where semantic-layer metrics quietly diverge from BI tools and dashboards.

## Top stories
- **[dbt v2.0 is GA](https://docs.getdbt.com/blog/dbt-v2-is-ga)** — dbt Developer Blog. The Fusion engine (rewritten in Rust, not Python) is now the default "dbt" distribution: it compiles projects up to 4x faster, catches invalid columns and type mismatches locally before hitting the warehouse, and replaces sprawling JSON artifacts with a queryable Parquet-based "dbt Information Schema." A companion post, **[What's the difference between dbt and dbt OSS?](https://docs.getdbt.com/blog/comparing-dbt-and-dbt-oss)**, clarifies that the free "dbt" distribution (proprietary license, more local features) is now the default recommendation over the fully Apache-2.0 "dbt OSS," which dbt Labs says "very few people" should need. *Why it matters:* this is the biggest architectural shift to the tool since dbt-core's Python rewrite, and it lands alongside Fivetran's new "agent-ready" integration push, announced separately at dbt Summit.
- **[dbt Semantic Layer vs Power BI: Where the Duplicate Metrics Actually Come From](https://medium.com/tech-with-abhishek/dbt-semantic-layer-vs-power-bi-where-the-duplicate-metrics-actually-come-from-f5dbef2c20ab?source=rss------dbt-5)** — Tech with Abhishek. A technical breakdown of how "revenue" defined in the dbt Semantic Layer can quietly diverge from "revenue" in a downstream Power BI report, and where that drift actually originates. *Why it matters:* metric duplication across the semantic layer and BI tool is one of the most common trust failures in analytics stacks.
- **[One Unified Explore in Semantic Layer Is a Performance Liability, Not a Design Virtue](https://medium.com/doubleverify-engineering/one-unified-explore-in-semantic-layer-is-a-performance-liability-not-a-design-virtue-57a6a3567063?source=rss------analytics_engineering-5)** — DoubleVerify Engineering. A real team's case against collapsing every metric into one giant semantic-layer "explore," arguing it trades query performance for a false sense of design simplicity. *Why it matters:* a concrete counterpoint from production experience to a common semantic-layer design pattern.
