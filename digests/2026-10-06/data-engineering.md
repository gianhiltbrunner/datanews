# A dbt incremental model silently deleted three months of finance data

Today's strongest signal from data engineering is another "the job looked healthy but wasn't" incident, this time a dbt incremental model that quietly erased months of finance data. Alongside it, a lakehouse metadata post digs into where table state should actually live, and a contrarian take challenges CDC's status as the default sync pattern. Most of the rest of the window was Medium tutorials, repeated vendor wire items (Cyient) and stock-adjacent news noise.

## Top stories
- **[Three months of sales vanished, and every dbt run was green](https://dev.to/vijaykumar13/three-months-of-sales-vanished-and-every-dbt-run-was-green-c9c)** — DEV. A dbt incremental model using delete+insert against SAP general-ledger data wiped three months of a finance report while every run reported success, because nothing was checking row counts against the source. *Why it matters:* incremental models can silently diverge from source truth for months unless someone actively tests the output, not just the run status.
- **[DuckLake 1.0 and Iceberg 1.11: What a Data Engineer Should Know](https://dev.to/datadriven/ducklake-10-and-iceberg-111-what-a-data-engineer-should-know-jp4)** — DEV. Argues that with both formats now mature, the real lakehouse question for 2026 has shifted from "which table format" to "where the metadata should live" — as files on object storage, or as rows in a database. *Why it matters:* metadata placement determines how a table fails (and how hard it is to recover) far more than which format's marketing you believed.
- **[Change Data Capture is the modern default for keeping systems in sync — challenged](https://dev.to/letusai15/change-data-capture-is-the-modern-default-for-keeping-systems-in-sync-challenged-gce)** — DEV. Argues CDC's at-least-once delivery means teams build idempotent consumers either way, so for most use cases the added cost of a Kafka Connect cluster and schema-coupling isn't buying the guarantee it promises. *Why it matters:* a useful check against reaching for CDC by default before confirming an app can't just write the ledger directly.
