# Netflix's orchestration engine Conductor turns out not to be dead after all

Netflix published a cluster of engineering posts today covering orchestration, metrics platforms and streaming storage, headlined by word that Conductor — written off as finished when Netflix ended it as open source — has more to its story. Elsewhere, Data Engineering Weekly argues orchestration engines need to be rebuilt around AI agents as their primary consumer, and practitioner discussion was thin.

## Top stories
- **[Netflix Conductor: The Next Chapter](https://netflixtechblog.com/netflix-conductor-the-next-chapter-41ad21067649?source=rss----2615bd06b42e---4)** — Netflix Tech Blog. Netflix revisits Conductor, the workflow orchestration engine it uses to stitch microservices into reliable business processes, picking the story back up after its 2023 announcement that it was ending the open-source project to focus on an internal fork. *Why it matters:* teams who adopted Conductor OSS and assumed the project was abandoned get an update on where Netflix has taken it since.
- **[DataJunction as Netflix's answer to the missing piece of the modern data stack](https://netflixtechblog.com/datajunction-as-netflixs-answer-to-the-missing-piece-of-the-modern-data-stack-92af926b40a5?source=rss----2615bd06b42e---4)** — Netflix Tech Blog. Netflix describes DataJunction, an open-source metrics platform built to centralize metric definitions so dashboards and experimentation tooling draw from one consistent number instead of duplicated logic. *Why it matters:* a concrete reference architecture for a problem — fragmented metric definitions — that most data platform teams have but few have solved in the open.
- **[TimeSeries Tiered Storage Journey: Kafka/Flink Streams to Native Cassandra Cold Reads](https://netflixtechblog.com/timeseries-tiered-storage-journey-kafka-flink-streams-to-native-cassandra-cold-reads-e59d597c9d60?source=rss----2615bd06b42e---4)** — Netflix Tech Blog. Netflix explains how it moved its petabyte-scale TimeSeries Abstraction platform off hot-only storage, using Kafka/Flink streams to push cold data into Cassandra for cheaper long-term reads without losing query access. *Why it matters:* a concrete pattern for controlling storage cost on high-throughput event data at scale.
- **[Behind the Scenes: Evolving Netflix's Ads Event Pipeline for Live — Part II](https://netflixtechblog.com/behind-the-scenes-evolving-netflixs-ads-event-pipeline-for-live-part-ii-826ebf9ad9fb?source=rss----2615bd06b42e---4)** — Netflix Tech Blog. Part two of Netflix's series on its Ads Event Publisher, the pipeline that collects, enriches and standardizes ad telemetry for frequency capping, billing and reporting consumers downstream. *Why it matters:* a detailed look at how an event pipeline gets adapted for the harder case of live content.
- **[The Self-Organizing Data Stack](https://www.dataengineeringweekly.com/p/the-self-organizing-data-stack)** — Data Engineering Weekly. Argues that once AI agents are the ones asking the questions, the orchestration engine has to shift from scheduling human-facing jobs to actively maintaining the data model those agents depend on. *Why it matters:* reframes orchestration roadmaps around agent consumers instead of dashboards.
