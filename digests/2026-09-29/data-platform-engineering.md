# Microsoft's FabCon Barcelona drops a wave of Fabric updates as ClickHouse joins OneLake

Microsoft's FabCon and SQLCon Europe conference in Barcelona drove most of the day's real news, with a broad Fabric feature wave and ClickHouse landing a native Fabric workload plus direct Iceberg-to-OneLake writes. Elsewhere, Claude Sonnet 5.5 and GPT-6 rolled out across AWS and Snowflake Cortex AI on the same day, and Databricks shipped full-text and vector search for its Postgres-based Lakebase. The rest of the window was largely Snowflake stock-ticker coverage and unrelated wire stories.

## Top stories
- **[Fabric September 2026 Feature Summary](https://community.fabric.microsoft.com/t5/Fabric-Updates-Blog/Fabric-September-2026-Feature-Summary/ba-p/5325825)** — Microsoft Fabric Blog. Timed to FabCon and SQLCon Europe in Barcelona, Microsoft calls this "one of our biggest updates yet," spanning governance, CI/CD, data engineering, AI-powered experiences, real-time intelligence and the new Fabric Apps layer. *Why it matters:* Fabric is visibly moving from a bundle of workspaces toward a governed platform with hooks for Copilot and third-party agents.
- **[ClickHouse expands collaboration with Microsoft, bringing Fabric integration, deeper OneLake interoperability, and enterprise deployment flexibility](https://clickhouse.com/blog/clickhouse-expands-collaboration-with-microsoft)** — ClickHouse Blog. ClickHouse's [Fabric workload](https://clickhouse.com/blog/clickhouse-for-microsoft-fabric) enters public preview for sub-second analytics on OneLake data, and ClickHouse can now [write Apache Iceberg tables directly to OneLake](https://clickhouse.com/blog/clickhouse-now-writes-to-microsoft-onelake), alongside BYOC availability in the Microsoft Marketplace. *Why it matters:* lets teams query and write OneLake data with ClickHouse's engine without a separate export step.
- **[Claude Sonnet 5.5 now available on AWS](https://aws.amazon.com/about-aws/whats-new/2026/09/claude-sonnet-5-5-aws/)** — AWS What's New. Claude Sonnet 5.5 landed on AWS and [AWS GovCloud (US)](https://aws.amazon.com/about-aws/whats-new/2026/09/claude-sonnet-5-5-aws-govcloud-us/) the same day [Snowflake Cortex AI added it](https://www.snowflake.com/content/snowflake-site/global/en/blog/claude-sonnet-5-5-snowflake-cortex-ai) alongside [GPT-6 Sol and Luna](https://www.snowflake.com/content/snowflake-site/global/en/blog/openai-gpt-6-sol-luna-snowflake-cortex-ai). *Why it matters:* the major data platforms are converging on offering the same frontier-model lineup as first-class, governed options inside the warehouse.
- **[Lakebase Search: State-of-the-art full text and vector search for Postgres](https://www.databricks.com/blog/lakebase-search-state-art-full-text-and-vector-search-postgres)** — Databricks Blog. Adds full-text and vector search to Databricks' Postgres-based Lakebase, aimed at the search demands of AI agents that traditional OLTP setups weren't built for.
- **[Your AI Bill Has Three Control Layers. Most Teams Only Build One.](https://medium.com/snowflake/your-ai-bill-has-three-control-layers-most-teams-only-build-one-c10e314ba97c?source=rss----34b6daafc07---4)** — Snowflake Engineering (Medium). Argues that treating AI cost governance as "set a budget" misses how a looping agent or a coding assistant left open all day can burn credits in patterns a monthly budget was never built to catch. *Why it matters:* AI spend doesn't behave like warehouse compute spend, and most teams' cost controls haven't caught up.

## Releases & tools
- **[Generally Available: Vector search and vector indexes in Azure SQL](https://azure.microsoft.com/updates?id=571800)** — adds `CREATE VECTOR INDEX` and `VECTOR_SEARCH` T-SQL for approximate nearest-neighbor search; paired with a new [Azure SQL Dev Hub](https://azure.microsoft.com/updates?id=572998) in public preview for connecting to Azure SQL from .NET, Python, Node.js and Java.
- **[Getting started with Apache Iceberg write support in Amazon Redshift – Part 3](https://aws.amazon.com/blogs/big-data/getting-started-with-apache-iceberg-write-support-in-amazon-redshift-part-3/)** — Redshift now supports evolving Iceberg table schemas and partition layouts through `ALTER` statements, with no data rewrites or pipeline rebuilds.
